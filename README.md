# 선박 정보 매칭 AI

> 항만 입출항 기록 한 행을 입력받아, 약 7.8만 척의 표준 선박 제원 카탈로그에서 같은 선박을 찾는 매칭 모델

**항만 문제해결을 위한 AI 기술 공모전** (해양수산부 주최 / 울산항만공사·한국정보산업연합회 주관 / 데이콘 운영)

| 최종 점수 | 순위 | 기간 |
|---|---|---|
| **0.89653** | 306위 | 2026.10.12 ~ 11.02 |

> 대회 규칙에 따라 데이터 파일과 데이터 내용은 포함하지 않습니다.

## 문제

- 입출항 기록의 선박명에는 철자 오류, 대소문자 차이, **한글 음차 표기**가 섞여 있고 제원값 일부가 비어 있음
- 평가: `0.7 × 한글 선박명 기록 정확도 + 0.3 × 비한글 기록 정확도`
- 코드 제출 방식: 비공개 test로 평가 서버에서 추론 (인터넷 차단, 20분 제한)

## 접근 방법

학습 모델 없이, 데이터 분석으로 찾은 단서들을 조합한 **규칙 기반 + 유사도 매칭 파이프라인**을 직접 구현했습니다.

1. **후보 축소 (톤수)**: 카탈로그와 같은 기준인 국제총톤수 ±10% 안의 선박만 후보로 선택
2. **한글 선박명 변환**
   - train의 한글↔영문 정답 쌍에서 단어 사전 자동 구축
   - 표기 패턴 규칙: 알파벳 약어 읽기(에스티 → ST), '제N' → No.N, 숫자 단어, 붙여 쓴 단어 분리
3. **이름 유사도 = 철자 유사도 + 자음 뼈대 유사도**
   - 한글과 영문을 모두 모음을 버린 '자음 뼈대'로 변환해 발음 기준으로 비교 (예: 갤럭시 / GALAXY → KRKS)
   - 뼈대가 짧으면 우연한 일치가 쉬우므로 비중 축소
4. **보조 단서 가산점**: 국적 일치, 선종 대응 확률, 톤수 근접도
5. **결측 대응**: 국제총톤수가 없으면 국내 총톤수 기준으로 후보 범위 조정

## 핵심 발견

- **국내 총톤수 vs 국제총톤수**: 한국 선적 선박은 국내 총톤수가 20~30% 작아 정답이 후보에서 누락 → 국제총톤수 우선 사용으로 한글 정확도 +10%p
- **검증 셋 설계가 성능 평가를 좌우**: 무작위 분할은 같은 선박이 학습·검증에 섞여 성능을 과대평가 → 선박 단위 분할, 교차 검증으로 보완
- **train과 test의 성격 차이**: 검증 한글 오류율 약 1%인데 test는 약 20% → 리더보드 결과를 단서로 test에 train에 없는 결측 패턴과 글자 단위 오타가 많음을 추정
- **지저분한 test일수록 보조 단서가 중요**: 국적·선종·톤수 근접도 가산점은 검증보다 test에서 효과가 2배 이상 컸음
- **실패한 아이디어의 재활용**: 톤수 범위 확대는 처음엔 점수를 떨어뜨렸지만, 톤수 근접도 가산점이라는 안전장치를 추가한 뒤 다시 도입해 성능 개선

## 배운 점

- 점수를 올리는 것보다 **"왜 오르고 왜 떨어졌는지"를 설명할 수 있는 것**이 다음 개선으로 이어짐
- 검증 점수와 실제 점수의 차이 자체가 가장 중요한 정보원
- 하루 한두 번의 제출을 test의 성격을 묻는 실험으로 활용

## 진행 기록

### Day 1 작업 환경 구성
- 구글 드라이브 마운트, 중첩 zip 해제
- 평가 서버 제출 구조(`data/`, `model/`, `output/`)와 동일한 작업 폴더 구성

### Day 2 데이터 구조 파악
- train(12,222행), catalog(78,595행) 컬럼 및 타입 확인
- 공통 단서: 선박명, 총톤수, 국적, 선종 / 기록에만 있는 정보: 호출부호(암호화), 입항 연도

### Day 3 기록 ↔ 정답 카탈로그 비교
- 한글 선박명: 영문 이름의 음차 표기, '호' 접미사, 표기 흔들림, 띄어쓰기 차이
- 영문 선박명: 대소문자 차이, 철자 오타
- 총톤수는 근접하지만 불일치 다수, 국적은 변경 가능, 선종은 일대일 대응 아님
- → 핵심 단서는 선박명, 다음은 톤수, 국적·선종은 보조 단서

### Day 4 베이스라인 분석 및 첫 제출
- 베이스라인 구조: script.py → baseline_lib.py → rf.pkl(랜덤 포레스트)
- 코드 제출 방식 이해: 서버가 비공개 test로 script.py를 실행해 결과 생성
- 리더보드: 베이스라인 0.362 (채점 기준 변경 후)

### Day 5 호출부호 단서 검증
- 가설: 호출부호가 같으면 같은 선박 → train 대응표로 test 정답 조회
- train 내부에서는 호출부호 1개당 정답 1개(100%), 무작위 분할 검증 시 72%를 100% 정확도로 조회
- 제출 결과 점수 변화 없음 → test 선박은 train과 호출부호가 겹치지 않음
- 교훈: 무작위 분할은 같은 선박이 학습·검증에 나뉘어 성능을 과대평가 → 선박 단위 분할 필요

### Day 6 검증 셋 재설계 및 오류 분석
- 선박 단위 그룹 분할로 검증 셋 구성 (겹치는 선박 0, 호출부호 조회율 0%)
- train 한글 기록 비율은 약 10%이나 점수 비중은 70%
- 베이스라인 검증: 한글 37.4% / 비한글 98.9% → 승부처는 한글
- 한글 표기 유형: 영문 약어의 알파벳 읽기, 영어 단어 음차, 비표준 로마자 고유명사, 중국어 이름, 숫자 유지

### Day 7 한글 단어 사전 매칭
- 단어 수가 같은 한글↔영문 정답 쌍을 순서대로 짝지어 단어 사전 구축
- 사전 변환(없으면 unidecode) → 톤수 ±10% 후보 → 문자열 유사도 최대
- 검증 한글 정확도 0.374 → 0.749 / 리더보드 0.652

### Day 8 국내·국제 총톤수 차이 발견
- 정답이 후보에서 빠진 기록은 모두 한국 선사 선박, 국내 총톤수가 국제총톤수보다 20~30% 작음
- 카탈로그는 국제총톤수 기준 → 국제총톤수 우선 사용
- 검증 한글 정확도 0.749 → 0.848 / 리더보드 0.690

### Day 9 검증-test 차이 분석 및 자체 파이프라인 구축
- 중복 선박, 카탈로그 톤수 결측 가설 기각
- 자체 매칭을 비한글에 적용 시 0.998 → 베이스라인 모델 제거, 전 과정 자체 구현으로 교체
- 리더보드 0.720 (베이스라인 모델의 비한글 성능이 과대평가였음을 확인)

### Day 10 자음 뼈대 비교 도입
- 한글·영문을 모두 자음 뼈대로 변환 (모음 제거, 비슷한 자음 통합)
- 철자 유사도 + 뼈대 유사도 합산: 검증 한글 0.848 → 0.914
- 사전에 없는 단어뿐인 기록에서 가장 크게 개선 → 리더보드 0.810

### Day 11 한글 표기 패턴 규칙
- '제N' → No.N, 알파벳 약어 읽기, 숫자 단어 규칙 추가
- 검증 한글 1.000 (단, 검증 오류를 보고 만든 규칙이라 과대평가) / 리더보드 0.815

### Day 12 교차 검증 및 결측 시뮬레이션
- 5-fold 그룹 교차 검증 도입 (한글 기록 1,191건 전체 평가)
- 톤수 결측 시뮬레이션: 정상 0.963 / 국제총톤수 없음 0.878 / 톤수 전부 없음 0.869
- 국내 톤수만 있을 때 범위 확대 → 리더보드 하락(0.780)

### Day 13 train-test 결측 패턴 차이 확인, 국적·선종 가산점
- train에는 '국제총톤수만 결측'인 행이 없지만 test에는 존재함을 리더보드로 확인
- 국적 대응표, 선종 대응 확률로 가산점 도입 (걸러내지 않고 점수만 가산)
- 교차 검증: 정상 0.963 → 0.983 / 톤수 없음 0.869 → 0.940 / 리더보드 0.850

### Day 14 번호 표기 정규화 및 복합어 분리
- 'NO.' 제거, 숫자 분리 후 맨 뒤로 이동, 붙여 쓴 단어를 사전 단어 기준으로 분리
- 교차 검증 한글: 정상 0.991 / 톤수 없음 0.948 / 리더보드 0.860

### Day 15 오타 시뮬레이션
- 검증 이름에 오타 주입: 띄어쓰기 제거 0.987 / 자음 변형 0.970 / 모음 변형 0.963 / 글자 빠짐 0.885
- 사전 유사 검색(자모 유사도): 효과 미미
- 짧은 뼈대 비중 축소: 리더보드 0.870 → test는 '글자 빠짐'에 가까운 성격으로 추정

### Day 16 가산점 재조정
- 단어 단위 부분 일치(token_set_ratio): 오타 없음·글자 빠짐 모두 하락 → 기각
- 오타 조건에서 국적·선종 가산점 재조정 (10, 20) → (15, 30) / 리더보드 0.875

### Day 17 톤수 근접도 가산점 및 최종 조정
- 후보 안에서 톤수가 정확히 같을수록 가산: 글자 빠짐 0.900 → 0.929 / 리더보드 0.891
- 톤수 근접도를 안전장치로 국내 톤수 범위 확대 재도입: 국내=국제인 경우 손해 0, 한국 선적 선박 0.898 → 0.978
- 비한글 가산점 추가 → 리더보드 **0.896** (최고점)
- 근접도 비중 test 확인: 30 → 0.895 / 40 → 0.896 / 50 → 0.892
